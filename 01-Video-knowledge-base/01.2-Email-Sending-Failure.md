<a id="project-background"></a>
## 📖 Project Background

"My email won't send" can mean the account is broken, the network blocks the connection, or the outgoing settings are wrong. Guessing wastes time, and a stuck contract email can cost business. This lab shows a repeatable way to narrow it down and fix it, using only what the screen shows.

- **Module 1 — Issue Identification:** Check receiving, reproduce the stuck email, read the first error.
- **Module 2 — Resolution & Verification:** Test the network port, fix the port and security, read the new error, fix authentication, and confirm the email arrives.
- **Module 3 — Customer Interaction:** Keep the customer informed without claiming a cause before it is proven.

> [!NOTE]
> The outgoing settings were broken on purpose to reproduce the problem. The fix is not complete until the email arrives at the recipient, not only until the Outbox is empty.

## 🗺️ Where Email Sending Can Break

```mermaid
flowchart LR
    A["✉️ Thunderbird"]:::a --> B["⚙️ SMTP settings<br/>Port / security / login"]:::b --> C["🌐 Network<br/>Port reachable?"]:::c --> D["📮 Gmail SMTP server"]:::d --> E["📬 Recipient"]:::e

    classDef a fill:#1A5276,stroke:#0B2E43,stroke-width:3px,color:#FFFFFF,font-weight:bold
    classDef b fill:#B9770E,stroke:#6E4409,stroke-width:3px,color:#FFFFFF,font-weight:bold
    classDef c fill:#943126,stroke:#571C16,stroke-width:3px,color:#FFFFFF,font-weight:bold
    classDef d fill:#117864,stroke:#083D33,stroke-width:3px,color:#FFFFFF,font-weight:bold
    classDef e fill:#2C3E70,stroke:#131B3A,stroke-width:3px,color:#FFFFFF,font-weight:bold
```

- **Network problem:** The port cannot be reached at all. Changing mail settings will not help until a reachable port is used.
- **Settings problem:** The port is reachable but the server refuses the message. The server's reply says what it wants.
- The steps below tell the two apart, so the cause is read from evidence and not guessed.

## 🟢 Module 2 — Resolution & Verification

**Objective:** Fix the sending failure and prove the email arrives.

### Step 6 — Test the network port ✅

```powershell
Test-NetConnection smtp.gmail.com -Port 25
```

```powershell
Test-NetConnection smtp.gmail.com -Port 587
```

<p align="center">
  <img src="screenshots/Exhibit7_port25_test.png" alt="Exhibit 7 - port 25 test fails" width="800"><br>
  <em>Exhibit 7 — Port 25: ping works (<code>PingSucceeded True</code>) but <code>TcpTestSucceeded False</code> with "TCP connect failed". The server is reachable, port 25 is not (Windows username hidden)</em>
</p>

<p align="center">
  <img src="screenshots/Exhibit10_port587_test.png" alt="Exhibit 10 - port 587 test works" width="800"><br>
  <em>Exhibit 10 — Port 587: <code>TcpTestSucceeded True</code> (Windows username hidden)</em>
</p>

Port 25 fails on this network and port 587 works at the connection level.

### Step 7 — Fix the port and security first ✅

Only the port (587) and connection security (STARTTLS) were changed. Authentication was left as it was.

<p align="center">
  <img src="screenshots/Exhibit9_port587_still_fails.png" alt="Exhibit 9 - port 587 STARTTLS, no authentication" width="850"><br>
  <em>Exhibit 9 — SMTP window after changing only port and security: Port 587, STARTTLS, authentication still "No authentication" (taken before OK, names hidden)</em>
</p>

<p align="center">
  <img src="screenshots/Exhibit15_smtp_details_587_secure.png" alt="Exhibit 15 - SMTP details" width="850"><br>
  <em>Exhibit 15 — Outgoing Server details: port 587, STARTTLS, No authentication, and "Successfully established a secure connection to smtp.gmail.com:587" (username hidden)</em>
</p>

### Step 8 — Send again and read the new error ✅

<p align="center">
  <img src="screenshots/Exhibit16_port587_error_starttls.png" alt="Exhibit 16 - STARTTLS error" width="850"><br>
  <em>Exhibit 16 — New error: "Must issue a STARTTLS command first" with a link to RFC 3207 (Google error ID and address hidden)</em>
</p>

The error changed, so the port fix did something. The message talks about STARTTLS even though STARTTLS was selected, and it does not mention authentication. The cause of this message was not proven in this lab. The next change tested was authentication.

### Step 9 — Fix authentication ✅

Set Authentication method to **OAuth2** and change nothing else. The User Name field must show the Gmail address.

<p align="center">
  <img src="screenshots/Exhibit3_smtp_settings_after.png" alt="Exhibit 3 - SMTP settings with OAuth2" width="700"><br>
  <em>Exhibit 3 — SMTP window before clicking OK: Port 587, STARTTLS, Authentication method OAuth2 (username hidden)</em>
</p>

### Step 10 — Send again and verify ✅

Outbox > menu > File > Send Unsent Messages. No error appeared and the Outbox emptied.

<p align="center">
  <img src="screenshots/Exhibit5_outbox_cleared.png" alt="Exhibit 5 - Outbox empty" width="850"><br>
  <em>Exhibit 5 — Outbox shows 0 messages after sending. An empty Outbox only means Thunderbird handed the mail off</em>
</p>

The real proof is on the recipient side:

<p align="center">
  <img src="screenshots/Exhibit4_test_email_received.png" alt="Exhibit 4 - test email received" width="850"><br>
  <em>Exhibit 4 — "Contract test" with body "TEST EMAIL." arrived in the recipient's Gmail Inbox (browser bar and profile pictures hidden)</em>
</p>

🎯 **Result:** The email was sent with port 587, STARTTLS and OAuth2, and it arrived.

| Check | Result |
|---|---|
| Port 25 TCP test | Failed ❌ |
| Port 587 TCP test | Succeeded ✅ |
| Port 587 + STARTTLS, no authentication | Sending failed with a STARTTLS error ❌ |
| Port 587 + STARTTLS + OAuth2 | Outbox emptied, no error ✅ |
| Recipient's Inbox | "Contract test" received ✅ |

### 🔍 Analyst Note — What Happens If the Fix Does Not Work

```mermaid
flowchart TD
    A["🚨 Send still fails"]:::alert --> B["🔎 Port test on 587"]:::work
    B -->|Fails| C["🌐 Network or firewall blocks it"]:::work
    B -->|Works| D["📖 Read the exact server error"]:::work
    D --> E["⚙️ Check security and authentication"]:::work
    C --> F["📨 Escalate to Network Team with evidence"]:::done
    E --> F

    classDef alert fill:#fdeaea,stroke:#C8102E,stroke-width:2px,color:#000
    classDef work fill:#e8f1fb,stroke:#005EB8,stroke-width:2px,color:#000
    classDef done fill:#eef7ee,stroke:#2ea44f,stroke-width:2px,color:#000
```

- Attach the exact error text and the port test results to the ticket.
- Do not leave temporary settings changes in place without documenting them.

> [!WARNING]
> Google sign-in and permission windows can expire if left open. Do the resend soon after changing the settings.

## 🟠 Module 3 — Customer Interaction

**Objective:** Keep a worried customer informed without over-promising or claiming a cause too early.

> *"My contract email to a client is stuck and won't send — I need it to go out today."*

```mermaid
sequenceDiagram
    autonumber
    participant C as 👤 Customer
    participant A as 🎧 Agent
    participant P as 💻 Customer PC

    rect rgba(0, 94, 184, 0.18)
    Note over C,P: Acknowledge and diagnose
    C->>A: Email stuck in Outbox, need it sent
    A->>C: I understand it is urgent, checking now
    A->>P: Check Inbox, Outbox, error text, port test
    end

    rect rgba(46, 164, 79, 0.18)
    Note over C,P: Fix and confirm
    A->>P: Fix port, security, authentication
    A->>P: Send the stuck email
    A->>C: Sent, please ask the recipient to confirm
    end
```

**Agent response given:**
- **During the fix:** "I understand this email is important, and I'm working on it now. I'll tell you as soon as it is sent."
- **After the fix:** "The email has been sent. Please ask your client to confirm they received it. If it happens again, contact us right away and I'll check the outgoing mail settings."

> The customer conversation is a scripted example. It was not tested with a real customer.

## ⚠️ Challenges & Fixes

| ❌ Challenge | ✅ Fix |
|---|---|
| The original script used Outlook, but this lab used Thunderbird with Gmail (OAuth2) | Rewrote the steps and environment for Thunderbird and Gmail |

<a id="scope-limitations"></a>
## 🚧 Scope & Limitations

- **Thunderbird and Gmail only.** Outlook and other mail providers were not tested.
- **OAuth2 instead of a password.** The Gmail account signs in with OAuth2, no app password was used. A password-based setup may behave differently.
- **Failure was set up on purpose.** The faulty settings (port 25, no security, no authentication) were entered by hand to reproduce the problem.
- **Cause of the STARTTLS error is not proven.** The error appeared with STARTTLS selected and no authentication. Changing authentication to OAuth2 was followed by a successful send, but whether OAuth2 alone would have worked on another port was not tested.
- **Port 25 result depends on the network.** Port 25 failed on this network. The test does not show who blocks it, and it can be different on another network or ISP.
- **No SPF, DKIM or DMARC checks.** Delivery to the recipient's Inbox was confirmed once, but spam filtering and sender authentication were not tested.
- **Single test email, single recipient.** One message to one address.
- **Customer conversation is scripted.** It was not tested with a real customer.

<a id="what-i-learned"></a>
## 🧠 What I Learned

- **Check receiving first.** If receiving works, the account is fine and the fault is on the sending side.
- **Test the port before changing settings.** `Test-NetConnection` shows whether the network lets the connection through at all.
- **Read the exact error text.** A changed error message means the last change did something.
- **Change one thing at a time.** Port and security first, authentication second, made it clear which change did what.
- **An empty Outbox is not proof.** Check the recipient's Inbox.
- **Do not claim a cause that was not proven.** Write what the screen showed and mark the rest as untested.
- **Review what access you give an app.** Google's permission screen lists what Thunderbird can read and change, so remove access when the test is over.
