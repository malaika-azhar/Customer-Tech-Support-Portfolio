## 🧭 Master Flowchart

Start here. Scope first, then one layer at a time.

| Step | Check | ✅ Yes | ❌ No |
|:---:|---|---|---|
| **1** | Other devices also affected? | Check router and ISP, then 📨 Escalate | Go to **Step 2** |
| **2** | Can the device connect? | Go to **Step 3** | 🔵 **Branch A** |
| **3** | Valid IP address? | Go to **Step 4** | 🟢 **Branch B** |
| **4** | `ping 8.8.8.8` works? | Go to **Step 5** | 🟠 **Branch C** |
| **5** | `ping google.com` works? | Resolved ✅ Test the customer's app | [DNS Flowchart](03.5-DNS-Flowchart.md) |

<a id="branch-a"></a>
## 🔵 Branch A — Cannot Connect

| Step | Check | ✅ Yes | ❌ No |
|:---:|---|---|---|
| **1** | Business login (username + password)? | Go to **Step 4** | Go to **Step 2** |
| **2** | Forget network, re-enter password. Connects? | Resolved ✅ | Go to **Step 3** |
| **3** | Update WiFi adapter driver. Connects? | Resolved ✅ | 📨 Escalate |
| **4** | Credentials correct? | 📨 Escalate (RADIUS logs needed) | Reset or unlock account, Resolved ✅ |

> An old saved password is the most common cause on one device. On a business network, only the network or identity team can read why RADIUS rejected the login.

---

<a id="branch-b"></a>
## 🟢 Branch B — No Valid IP

| Step | Check | ✅ Yes | ❌ No |
|:---:|---|---|---|
| **1** | `ipconfig /release` then `/renew`. Valid IP? | Resolved ✅ | Go to **Step 2** |
| **2** | Do other devices get an IP? | Go to **Step 3** | DHCP down or pool full, 📨 Escalate |
| **3** | Forget network, reset adapter. Valid IP? | Resolved ✅ | 📨 Escalate |

> `169.254.x.x` is an automatic fallback address. The device asked for an IP and nobody answered.

---

<a id="branch-c"></a>
## 🟠 Branch C — No Internet or Weak Signal

| Step | Check | ✅ Yes | ❌ No |
|:---:|---|---|---|
| **1** | `ping` default gateway works? | Router WAN or ISP fault, 📨 Escalate | Go to **Step 2** |
| **2** | Move closer, check signal. Better? | Resolved ✅ | Go to **Step 3** |
| **3** | Switch band, update driver. Better? | Resolved ✅ | 📨 Escalate |

> Gateway ping fails: the problem is the WiFi link. Gateway ping works but the internet does not: the problem is past the router.

<a id="escalation"></a>
## 📨 Escalation Evidence

| Fault location | Send to |
|---|---|
| Router, access point, DHCP, RADIUS | Network team |
| Internet beyond the router | ISP |
| Driver or adapter hardware | Endpoint / hardware team |

Attach to the ticket:

- `ipconfig /all` output
- `netsh wlan show interfaces` output (SSID, Signal, Channel)
- Ping results for gateway, `8.8.8.8` and `google.com`
- Exact error message, start time and number of devices affected
- Everything already tried, in order

<a id="commands"></a>
## 💻 Command Reference

| Command | Used for |
|---|---|
| `ipconfig /all` | Read IP, gateway, DHCP and DNS servers |
| `ipconfig /release` + `/renew` | Ask DHCP for a new address |
| `ping <gateway>` | Test the local WiFi link |
| `ping 8.8.8.8` | Test internet without DNS |
| `ping google.com` | Test name resolution |
| `netsh wlan show interfaces` | Read signal, channel and radio type |
